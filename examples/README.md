# 配置草稿说明

这里的三个 YAML 是**产品合同示例，不是已经开发完成的 CLI 配置**。它们可供创建 DTO、表单和发布校验器时使用。

`task-draft.yaml` 描述一个假定存在的订单 API 任务，不来自对任何用户业务仓库的实际审查。`profile-draft.yaml` 特意保留 REPLACE_ 字段，避免伪造模型 ID、认证路径和 CLI 版本。`experiment-draft.yaml` 展开为 1 个任务 × 3 个配置 × 1 次 = 3 个 Trial，面向 v0.2。

任务与参与对比的 Profile 在该示例中使用同一个已准备、含固定版本 CLI 的环境。不得把不同工具链镜像悄悄视为同一环境。

发布过程必须验证所有引用确实存在、doctor 有效、账号和环境已授权、时间和字节限制为正，再将分支/镜像/配置转换为不可变快照。任何 REPLACE_ 字段都应阻止发布。

YAML 只是输入。最终执行快照采用规范 JSON，保存真实 commit、内容摘要、CLI/模型来源、verifier 摘要、执行协议与环境。不要把含 master 的草稿直接当作可复现实验。

网络策略引用不是沙箱实现。没有实际强制出口措施，不能把 `network_policy_ref` 填成某个名称就显示网络已受限。类似地，`account_ref` 与 `credential_ref` 不包含真实密钥，运行时只由授权控制端解析。

这些示例已做语法检查；尚不存在本项目实现可用于验证它们的端到端执行。
